Phase 1 Auth foundation — JWT + roles ~2–3 days ▶
Backend
MySQL schema: users table (id, name, email, password_hash, role, created_at)
POST /api/auth/register — bcrypt hash, return JWT
POST /api/auth/login — verify password, return JWT
GET /api/auth/me — protected, returns current user
JWT middleware — authGuard for all protected routes
Role field: user | coach | admin (even if unused now)
Frontend
Nuxt route middleware: redirect to /login if no token
useAuth composable — login(), register(), logout(), user ref
Pinia authStore — persist JWT in localStorage
/auth/register page — name, email, password form
/auth/login page
Axios interceptor — attach Bearer token to all requests
Done when: You can register, log in, hit a protected endpoint, and get 401 if no token. Roles stored but not enforced yet.
Phase 2 User profile + onboarding setup screen ~3–4 days ▶
Backend
user_profiles table: user_id FK, gender, age, height, weight, goal, sport, level, equipment (JSON), days_per_week, session_duration, training_philosophy
POST /api/profile/onboarding — create/upsert profile
GET /api/profile — return current user's profile
Validation: required fields, age range, weight range
Flag: onboarding_completed boolean on users table
Frontend
/onboarding multi-step page (7 steps, progress bar)
Step 1: gender + age
Step 2: height + weight
Step 3: sport selection cards
Step 4: fitness level
Step 5: equipment checkboxes
Step 6: training philosophy cards (HIT, PPL, 5×5, GVT…)
Step 7: days/week + session duration
useProfile composable — submit, fetch, store in Pinia
Route guard: redirect to /onboarding if profile incomplete
Done when: New user registers → goes through 7-step onboarding → profile saved to DB → redirected to /home (empty for now).
Phase 3 Exercise library sync from ExerciseDB ~2 days ▶
Backend
exercises table: id, name, target_muscle, secondary_muscles, equipment, difficulty, gif_url, instructions (JSON)
One-time seed script: fetch all exercises from ExerciseDB API → store in MySQL
GET /api/exercises — filter by muscle, equipment, level
GET /api/exercises/:id — single exercise detail
Index on target_muscle + equipment for fast filtering
Frontend
No user-facing UI needed yet
Verify endpoint works via browser / Postman
Confirm GIF URLs load correctly in an img tag
Done when: 11K exercises seeded in DB. GET /api/exercises?muscle=quads&equipment=barbell returns filtered list with GIF URLs.
Phase 4 Program generation engine + home screen ~4–5 days ▶
Backend
workout_programs table: id, user_id, sport, philosophy, level, week_structure (JSON), created_at
program_days table: id, program_id, day_number, week_number, exercises (JSON array)
ProgramGenerator service: muscle distribution map per sport + philosophy
Exercise selector: filter by muscle %, equipment, level → pick top N
Periodization builder: assign sets/reps/intensity per week phase
Day distributor: spread exercises across chosen days/week
POST /api/programs/generate — triggers full generation, returns program
GET /api/programs/active — returns user's current program
GET /api/workouts/today — returns today's exercise list with prescribed sets/reps/weight
Frontend
/home page — shows current week, intensity phase, today's exercise list
Each exercise card: name, target muscle, prescribed sets × reps @ weight
"Start Workout" button → navigates to /workout
useProgram composable — fetch active program, today's session
Auto-trigger program generation after onboarding if no active program
Loading state while program generates
Done when: After onboarding, /home shows a real 8-week program. Today's workout is listed with correct exercises filtered by sport + equipment + philosophy.
Phase 5 Workout logging + progression detection ~3–4 days ▶
Backend
workout_logs table: id, user_id, program_day_id, duration_sec, completed_at
exercise_logs table: id, workout_log_id, exercise_id, sets_done, reps_done, weight_done, sets_prescribed, reps_prescribed, weight_prescribed, rpe, notes, progression_status
POST /api/logs/exercise — save single exercise log, run progression detection
POST /api/logs/workout/complete — close workout session, save duration
Progression detection logic: weight_increase / reps_increase / easy / very_hard / matched
GET /api/logs/history — paginated workout history
Frontend
/workout/exercise/[index] page — one exercise at a time
GIF display, prescribed values shown
+/- buttons for sets, reps, weight (2.5kg steps)
RPE selector 1–10
Optional notes textarea
"Log & Next" → save + advance to next exercise
Workout complete screen — total time, summary
useWorkout composable — track session state in Pinia
Done when: Full workout loop works end-to-end. User starts workout → logs all exercises → sees complete screen → data in DB with progression status.
Phase 6 Progress tracking + personal records ~2–3 days ▶
Backend
GET /api/progress/prs — personal records per exercise (max weight ever)
GET /api/progress/exercise/:id — weight over time for one exercise
GET /api/progress/volume — weekly total volume (sets × reps × weight)
GET /api/progress/history — list of completed workouts with summary
1RM estimator: Epley formula (weight × (1 + reps/30))
Frontend
/progress page — charts + PR list
Weight-over-time line chart per exercise (Chart.js or recharts)
PR cards per exercise with 1RM estimate
Weekly volume bar chart
Workout history list (date, duration, exercises done)
Bottom navigation: Home / Workout / Progress / Profile
Done when: /progress shows real charts from logged data. PRs update automatically after each workout. MVP is fully functional end-to-end.
